# 预警通知

流量异常、拦截暴增、CPU 过高等情况，用邮件提醒你。当前**真正能发的是邮件**（其它通道多为预留）。

面板入口：**观测 → 预警通知**。

证书到期提醒在 [证书管理](./certificates.md) 里配，也走同一套邮件通道。

## 开始前：先通邮件

1. 打开 [系统设置 → 通知通道](./settings.md)
2. 配好 SMTP，点 **测试发送**
3. 收到测试信后再回来建预警

通道没通，策略再漂亮也送不到。

## 怎么加一条预警

1. 点新建，填名称并启用
2. 选 **条件类型**（见下）和阈值、时间窗口、站点范围
3. 勾选已配好的邮件通道
4. 设 **冷却时间**（例如 5～15 分钟），避免刷屏
5. 用压测或观察期确认能收到信

### 站点范围

| 选项 | 含义 |
|------|------|
| 全部站点合计 | 所有站加总后再判断 |
| 任意站点 | 任一站达到就触发 |
| 指定站点 | 只盯某一个站 |

## 条件类型（白话）

**流量异常**

- 相对平时基线偏高 / 偏低
- 请求量或 QPS 超过固定值
- 回源量 / 回源 QPS 异常
- 日志采样进入自动取证（一般无需再填阈值）

**安全事件**

- 一段时间内拦截次数太多
- 拦截率（占比）太高  

常见窗口：5 / 15 / 30 / 60 分钟。

**系统 CPU**

- 容器 CPU 过高，或宿主机 CPU 过高（按面板选项填窗口和百分比）

## 和新手建议

1. 先配「拦截次数」或「流量高于基线」
2. 冷却设 5～15 分钟
3. 确认能收到后再加 CPU、回源类

## 和 AI 防护的关系

[AI 防护策略](./ai-guard.md) 的触发条件和这里类似，但触发后会走分析、给规则建议，不只是发信。可以一起用：预警叫醒人，AI 给建议。

## 注意

- 没配 SMTP 却以为「策略坏了」
- 冷却太短 → 邮箱被刷爆
- 流量很不稳定时，基线类容易误报——可先用绝对值 / QPS
